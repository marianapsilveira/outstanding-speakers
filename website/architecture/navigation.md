# Navigation

## Purpose

The navigation should help users understand the website structure quickly and move between discovery, speaker exploration, resources and booking without friction.

The website should feel simple, curated and intentional. Navigation should not expose unnecessary complexity.

---

## Primary Navigation

Main navigation items:

- Speakers
- Resources
- Become a Speaker

Primary CTA:

- Book a Speaker

---

## Navigation Behavior

The primary navigation should appear consistently across main pages:

- Home
- Speakers
- Speaker Profile
- Resources
- Become a Speaker

The booking flow may keep a simplified navigation to reduce distraction and keep users focused on completing the request.

## Primary CTA Logic



### Book a Speaker

Purpose:

Start the booking request flow.

Behavior:

- From Home: opens generic booking entry point or speaker selection
- From Speakers: opens booking flow after speaker selection
- From Speaker Profile: opens booking flow with selected speaker pre-filled
- From Resources: opens generic booking entry point

The CTA should remain visible on key discovery pages.

## Booking Flow Navigation

The booking flow should reduce global navigation to keep users focused.

Recommended behavior:

- Show logo
- Show progress indicator
- Provide Back button
- Avoid full navigation menu during the flow
- Keep Exit or Cancel available if needed

The flow should communicate progress clearly across steps.

Example:

1. Speaker
2. Session
3. Audience
4. Logistics
5. Review / Message
6. Confirmation

---



## Mobile Navigation

Mobile navigation should prioritize:

- Speakers
- Resources
- Book a Speaker

Recommended pattern:

- Collapsed menu
- Persistent primary CTA if possible
- Clear hierarchy between navigation links and conversion CTA

---



## Navigation Principles



### 1. Keep the system small

Avoid adding navigation items unless they support a clear user journey.

### 2. Make booking visible but not aggressive

The CTA should be easy to find, but the platform should still feel human and trust-based.

### 3. Separate discovery from action

Users should be able to learn before being pushed to book.

### 4. Avoid duplicate destinations

If “Stories” and “Speaker Profiles” serve the same purpose, do not split them prematurely.

### 5. Support return paths

After viewing a speaker profile or resource, users should always have an easy path back to speakers or booking.
